# Исправление проблемы с Telegram авторизацией

## Проблема
Сервер возвращает 401 ошибку при отправке формы из-за несоответствия токена бота и бота в Telegram виджете.

## Причина
- BOT_TOKEN в переменных окружения принадлежит одному боту
- BOT_USERNAME указывает на другого бота
- Telegram виджет подписывает данные токеном бота из BOT_USERNAME
- Сервер проверяет подпись токеном из BOT_TOKEN
- Подписи не совпадают → 401 ошибка

## Решение

### 1. Определите правильного бота
Запустите сервер и посмотрите в логи:
```bash
python -m uvicorn backend.main:app --reload --port 8000
```

В логах будет:
```
BOT_USERNAME из конфига: fivechairs_bot
Реальный username бота: @some_other_bot
❌ НЕСООТВЕТСТВИЕ: BOT_USERNAME (fivechairs_bot) ≠ token.username (@some_other_bot)
```

### 2. Выберите стратегию

#### Вариант A: Использовать существующий токен
Если токен принадлежит нужному боту:
1. Узнайте username бота через API:
   ```bash
   curl "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getMe"
   ```
2. Обновите BOT_USERNAME в переменных окружения

#### Вариант B: Получить новый токен для нужного бота
Если нужен конкретный бот (@fivechairs_bot):
1. Откройте @BotFather в Telegram
2. Найдите бота: `/mybots` → выберите `fivechairs_bot`
3. Получите новый токен: `Revoke Token` → `Generate New Token`
4. Обновите BOT_TOKEN в переменных окружения

### 3. Настройте переменные окружения

#### Для локальной разработки:
```bash
cp env.template .env
# Отредактируйте .env файл
```

#### Для продакшена (Railway/Render):
Установите переменные окружения в панели хостинга:
- `BOT_TOKEN` - токен от BotFather
- `BOT_USERNAME` - username бота (без @)
- `DATABASE_URL` - строка подключения к БД

### 4. Проверьте настройку
Запустите сервер - в логах должно быть:
```
✅ Токен и юзернейм соответствуют: @your_bot_username
```

### 5. Тестирование
1. Откройте анкету в браузере
2. Заполните форму до конца
3. Нажмите "Войти через Telegram"
4. Форма должна отправиться без ошибок

## Безопасность

### ❌ Что НЕ делать:
- Не храните токены в репозитории
- Не коммитьте .env файлы
- Не используйте один токен для разных ботов

### ✅ Что делать:
- Используйте переменные окружения
- Ротируйте токены при компрометации
- Проверяйте соответствие токена и username

## Отладка

### Проверка подписи локально:
```python
import hmac
import hashlib

# Данные из логов
data = "auth_date=1758795379\nfirst_name=Костя\nid=5878097626\nusername=kostiakunak"
token = "ВАШ_ТОКЕН"

# Правильный способ
secret = hashlib.sha256(token.encode()).digest()
calculated = hmac.new(secret, data.encode(), hashlib.sha256).hexdigest()
print(f"Calculated: {calculated}")
print(f"Received:   4405732a...")  # из логов
print(f"Match: {calculated == '4405732a...'}")
```

### Логи для отладки:
- `BOT_USERNAME из конфига` - что ожидает сервер
- `Реальный username бота` - что возвращает Telegram API
- `Calculated hash` - что посчитал сервер
- `Received hash` - что пришло от виджета

## После исправления
1. Убедитесь, что форма отправляется без ошибок
2. Проверьте, что данные сохраняются в БД
3. Убедитесь, что пользователь перенаправляется в бота
4. Протестируйте на разных устройствах
